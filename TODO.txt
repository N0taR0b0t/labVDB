What "moving to production" means here
- Single cheap server (Hetzner 8 GB / 80 GB SSD, ~$6.59/mo recommended)
- Server Qdrant via docker-compose (already provided)
- You are the only user for now — test in prod is fine

Production checklist (ordered)

1. Deploy to a server
- Provision a Hetzner (or equivalent) CPU VPS
- Install Docker + Docker Compose
- Clone repo, copy .env from .env.example, set QDRANT_URL=http://localhost:6333
- Run: docker-compose up -d
- Run: uvicorn search_api:app --host 0.0.0.0 --port 8000

2. Run the initial full index
- Copy pdfs/ to the server
- Run: python indexer.py --pdf-dir pdfs/
- This is the one-time ~4 hour batch job for 182 docs (scales to overnight for 10k)
- Verify with: curl http://localhost:8000/stats

3. Verify search works end-to-end
- Hit /health — confirms Qdrant connectivity
- Run a few queries against /search
- Spot-check /chunk/{chunk_id} returns full text for a result
- Dense search p50 should be 10–50ms on server Qdrant (vs 17ms embedded at this corpus size)

4. Wire hybrid reranking into /search  ← first real feature work
- Current state: /search returns dense-only results; rerank_hybrid exists but is not called
- Required: call rerank_hybrid on the dense candidates before returning results
- Add optional ?hybrid=false query param to compare modes if useful
- This matters most for scientific terms, gene names, assay abbreviations

5. Add section filter to /search
- build_filter() already supports section; /search does not expose it
- Add ?section= query param alongside existing doc_id and filename

6. Expose manifest stats in /stats
- manifest_stats() exists (returns per-status counts)
- Add it to the /stats response so you can see failed/duplicate/indexed counts from the API

7. Write a README
- Setup (clone, .env, docker-compose up, indexer.py)
- Query API usage with curl examples
- How to add new PDFs (drop in pdfs/, rerun indexer.py)
- Known limitations (embedded vs server Qdrant, no auth)
