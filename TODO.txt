Production checklist (ordered)

1. Deploy to a server ✓
- Ubuntu 24.04 IONOS VPS
- Installed: docker.io, docker-compose, python3-pip, python3.12-venv
- python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
- cp .env.example .env  (QDRANT_URL=http://localhost:6333)

What comes next (ordered by impact)

A. Progressive full-text loading in the UI ✓
- Click-to-expand: clicking a result fetches /chunk/{chunk_id} and swaps in full text inline
- Error recovery: failed fetches are retried on re-click
- section shown in result meta line

B. Section filter controls in the UI ✓
- Section input added to the filter row; wires to ?section= on /search

C. Section detection during indexing ✓
- SECTION_ALIASES expanded from 10 to 37 entries covering common biomedical headings
- canonicalize_section now does sliding-window prefix matching for numbered headings
  (e.g. "3.2 Statistical Analysis" → "Methods")
- Word-count guard raised from 8 to 12 words
- current_section threaded across pages in indexer.py so multi-page sections carry forward
- Full re-index running as of 2026-03-19 to populate section metadata

D. Header/footer suppression ✓
- is_junk_block() added; drops blocks that are: too short (<20 chars), no alpha chars,
  running headers (mostly-uppercase line + bare page number), or <3 distinct tokens
- Applied before chunking; result: ~4-10% fewer chunks per document

E. Intra-document result deduplication ✓
- _deduplicate() added in search_api.py; default max_per_doc=2
- fetch_limit raised to limit*5 so there are enough candidates after dedup
- ?max_per_doc= param on /search (1–10); cap skipped when doc_id or filename filter active

F. Validation coverage ✓
- tests/test_labvdb_core.py: 22 tests covering doc_id stability, duplicate detection,
  is_junk_block, and canonicalize_section; all passing
